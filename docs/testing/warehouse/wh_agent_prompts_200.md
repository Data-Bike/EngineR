# 200 промптов управляющего складом «СК-Логистик»

Сценарий исполняется агентом последовательно, сверху вниз, **исключительно
через EngineR MCP** (`http://localhost:8020/mcp`, JSON-RPC `tools/call`,
токен `admin` из `docs/testing/warehouse/.wh_tokens.json`). Агент хранит
`public_id` созданных объектов и ссылается на них в последующих промптах.
Коды объектов уникальны внутри прогона; при повторном прогоне identity-
дедупликация вернёт `outcome: deduplicated` — это успех, а не ошибка.

**Каталог:** все `wh_*` типы, сущности и схема живут в каталоге `wh`
(«Склад», docs/28). MCP-инструменты принимают необязательный `catalog:
"wh"` — тип сам задаёт каталог, поэтому без параметра всё попадает в
`wh` автоматически; фильтр `catalog` на list/query сужает выдачу до
этого каталога. Права, поля и связи каталого-зависимы: «Тип ФЛ» в `wh`
не обязан совпадать с одноимённым типом в `general`.

Доменная схема (ревизия 2): `person`, `legal_entity`, `wh_warehouse`,
`wh_zone`, `wh_product`, `wh_stock`, `wh_inbound`, `wh_outbound`,
`wh_inventory`, `wh_supplier`, `wh_client`, `wh_contractor`, `wh_cargo`,
`wh_waybill`, `wh_payment`, `wh_expense`, `wh_hold`, `wh_contract`.

Ключевые рёбра: `wh_located_in` (зона→склад), `wh_keeper` (person→склад),
`wh_located_in`, `wh_stock_product`/`wh_stock_zone`/`wh_stock_contract`,
`wh_supplied_by` (товар→юрлицо), `wh_product_supplier` (товар→wh_supplier),
`wh_inbound_to/from/supplier/item/contract`, `wh_outbound_from/to/client/
item/contract/carrier/receiver`, `wh_cargo_in` (груз→зона),
`wh_cargo_on` (груз→накладная), `wh_waybill_inbound/outbound/carrier`,
`wh_payment_for` (→накладная)/`wh_payment_client`/`wh_payment_supplier`/
`wh_payment_contract`, `wh_expense_wh`, `wh_hold_on` (→оплата)/
`wh_hold_party`, `wh_contract_party`/`wh_contract_wh`, `wh_counted_in`.

### Типы полей (field kinds)

Каждое поле типа декларирует `kind`. В `fields`-шорткате значение можно
писать «голым» — API коэрсит по объявленному кинду (`apps/api/src/
field_kinds.rs`). Неверные значения возвращают 422, а не пишутся текстом.

| kind | пример значения | хранится как |
|---|---|---|
| `text` | `"приёмка"` | Text |
| `localized_text` / `ltext` | `{"value":"Привет","language_tag":"ru"}` | Text + тег языка |
| `boolean` | `true`, `"yes"`, `1` | Boolean |
| `integer` | `5`, `12.0`, `"7"` | Integer (дробное → 422) |
| `decimal` / `percent` | `1200.5`, `"16%"` | Decimal (не-число → 422) |
| `money` | `450000`, `{"amount":"12.5","currency":"USD"}` | Money (валюта ISO 4217, дефолт RUB) |
| `measurement` | `{"amount":1200,"unit":"kg"}` или `1200` + `unit` в схеме | Measurement |
| `date` | `"2026-10-20"` | Date |
| `instant` | `"2026-10-20T14:30:00Z"` (RFC 3339) | Instant (UTC) |
| `local_datetime` / `datetime` | `"2026-10-20T14:30"` + `zone`; date-only = полночь | LocalDateTime / Instant при офсете |
| `time` | `"09:30"`, `"09:30:00"` | Text (валидируется) |
| `timezone`, `duration` | `"Europe/Moscow"`, `"P30D"` | Text |
| `uuid` | `"01a1…"` | Uuid |
| `uri` / `url` | `"https://…"` | Uri |
| `email` | `"a@b.ru"` (обязателен `@`) | Email |
| `phone` | `"+74951112233"`, число, `extension` | Phone |
| `enum` / `dictionary` | значение строго из `values[]` поля → иначе 422 | Text |
| `entity` / `entity_reference` | `"<public_id>"` или `{"entity_id":"<public_id>"}` | Entity object |
| `tags` / `multi_value` / `repeating_group` | `"a, b"` или `["a","b"]` | Json-массив |
| `address` / `contact` / `json` | любой JSON | Json |
| `geo` | GeoJSON `{"type":"Point","coordinates":[…]}` | Geo |
| `blob` / `file` / `document` | `{"content_hash":"<64 hex>","size":N,"mime":"…"}` | Blob |
| `derived` | **нельзя писать** — вычисляемое | 422 |

Правила записи:
- `{"entity_id": "<public_id>"}` — ссылка только на entity-поле или
  недекларированном предикате; в `json`-поле тот же объект — данные.
- Explicit `{"kind": "…", "value": …}` уважается, но не может
  противоречить декларированному кинду (enum-allowlist и entity/scalar
  проверяются всегда; регистр кинда не важен).
- Рёбра — через `relations.create`; `{entity_id}` в `fields` тоже
  создаёт entity-значение на relation-предикате.
